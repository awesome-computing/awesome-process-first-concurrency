# Contributing

Thanks for considering a contribution to Awesome Process-First Concurrency!

## Guidelines

- **Stay on thesis.** Resources should genuinely relate to process-based, queue-based, or "just enough" broker-based concurrency — or to the actor/distributed-bus side of the decision, when the resource helps someone judge when to cross that line.
- **Real and current.** Link to actively maintained projects, or clearly-labeled classic/historical references (papers, talks) where the ideas still hold up. No dead links, no vaporware.
- **One entry, one line.** `[Name](url) — short, factual description of what it is and why it fits.` No marketing language.
- **Alphabetical within each category.**
- **No self-promotion spam.** If you're the author of a project you're adding, say so in the PR description — that's fine, just be upfront.
- **Check for duplicates** before opening a PR or issue.

## How to propose a resource

- Easiest: open an issue using the [Suggest a resource](../../issues/new?template=suggest-resource.yml) template.
- Or: fork, add your entry to the right category in `README.md`, and open a PR. Small, single-purpose PRs are easiest to review, but batched additions are fine too if they're all clearly on-thesis.

## Removing a resource

If something is unmaintained, dead, or no longer fits, open an issue explaining why (or a PR removing it directly).
